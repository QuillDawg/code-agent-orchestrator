# Landscape notes: coding-agent orchestration and workflow UX

Date: 2026-09-03.

Method: every bullet below was taken from a page fetched on that date (official docs, changelogs, source repos, first-party blogs, or the tool's own README). No secondary write-ups were used. Facts are stated as the page stated them; version numbers and star counts are "as of fetch". Where a claim is the vendor's own benchmark it is marked "self-reported". Items that could not be confirmed from a primary source are listed at the end. This file records facts only; feature recommendations are left to the main author.

Context for the reader: `cao` runs YAML DAG workflows of isolated `claude -p` / `codex exec` sessions, one process per task, parallel tasks in git worktrees, JSON results passed downstream, persisted/resumable runs, an Ink dashboard for transcripts/cost/files and answering permission prompts, approval gates, `when` conditions, retries, hooks, per-task model/effort. It never pushes or opens PRs.

## 1. Claude Code (headless mode, sessions, hooks, worktrees, cost)

### Headless / print mode
- **`-p`/`--print` runs non-interactively; `--output-format` accepts `text`, `json`, `stream-json`; `--input-format` accepts `text`, `stream-json`; `--include-partial-messages` requires `--print` and `stream-json`** — source: https://code.claude.com/docs/en/cli-reference
- **`--json-schema` returns validated JSON matching a schema in the result's `structured_output` field (print mode only); an invalid schema exits with `Error: --json-schema is not a valid JSON Schema` (v2.1.205+)** — source: https://code.claude.com/docs/en/headless
- **`--max-turns` limits agentic turns and exits with an error at the limit; `--max-budget-usd` is "Maximum dollar amount to spend on API calls before stopping (print mode only)"; `--no-session-persistence` suppresses transcript writes for one `-p` run** — source: https://code.claude.com/docs/en/cli-reference
- **`--bare` skips auto-discovery of hooks, skills, custom commands, subagents, plugins, MCP servers, auto memory and CLAUDE.md, never reads OAuth/keychain (needs `ANTHROPIC_API_KEY` or `apiKeyHelper`), and "will become the default for `-p` in a future release"; context is re-added via `--append-system-prompt`, `--settings`, `--mcp-config`, `--agents <json>`, `--plugin-dir`** — source: https://code.claude.com/docs/en/headless
- **`--effort` accepts `low`, `medium`, `high`, `xhigh`, `max`, `ultracode`; `--fallback-model` enables automatic fallback when the primary model is overloaded; `--agents` defines subagents dynamically via JSON** — source: https://code.claude.com/docs/en/cli-reference
- **stream-json: `system/init` is the first event and carries `plugins`, `plugin_errors`, `mcp_servers`, `mcp_server_errors` (omitted when empty, "so a CI gate can fail on a non-empty array") and a `capabilities` array for feature detection (v2.1.205+); `system/api_retry` events carry `attempt`, `max_retries`, `retry_delay_ms`, `error_status`, `error` category** — source: https://code.claude.com/docs/en/headless
- **Subagent messages in the stream carry `parent_tool_use_id`; by default only subagent `tool_use`/`tool_result` blocks are emitted; `--forward-subagent-text` (or `CLAUDE_CODE_FORWARD_SUBAGENT_TEXT`) also emits subagent text/thinking so a full nesting tree can be rebuilt (v2.1.211+, nested depth from v2.1.219)** — source: https://code.claude.com/docs/en/headless
- **Exit codes: 0 on success, non-zero on failure; SIGTERM exits 143, kills the process tree of running Bash commands, runs only `SessionEnd` hooks, and leaves the turn unfinished so a later `--resume` continues it; stdin is capped at 10 MB** — source: https://code.claude.com/docs/en/headless
- **Background Bash tasks started during `-p` are terminated ~5 s after the final result; background subagents are waited for, capped at 10 minutes idle by default (`CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS`, v2.1.182+)** — source: https://code.claude.com/docs/en/headless
- **`--output-format json` includes `total_cost_usd` and a per-model breakdown; both are "client-side estimates" that can differ from the bill** — source: https://code.claude.com/docs/en/headless
- **`--restricted` / `CLAUDE_CODE_RESTRICTED=1` removes the built-in tools that run commands (changelog 2.1.248/2.1.250)** — source: https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md

### Sessions
- **`--continue`/`-c` loads the most recent conversation in the directory but skips background sessions, `-p`/SDK sessions and `/loop` sessions; `--resume`/`-r` resumes by ID or name or opens a picker; `--session-id` must be a UUID; `--fork-session` creates a new ID when resuming; `--name`/`-n` sets a display name shown in `/resume` and the terminal title; `--from-pr <n>` filters the picker to sessions linked to a PR** — source: https://code.claude.com/docs/en/cli-reference
- **`claude --resume <session-id>` works from any directory since v2.1.223 (searches every project on the machine); `-p`/SDK sessions are excluded from the picker but resumable by ID** — source: https://code.claude.com/docs/en/sessions
- **Transcripts are JSONL at `~/.claude/projects/<project>/<session-id>.jsonl`; "The entry format is internal to Claude Code and changes between versions"; retention via `cleanupPeriodDays` (30 days default); `CLAUDE_CONFIG_DIR` and `CLAUDE_CODE_PROJECT_DIR_NAME` (v2.1.234+) relocate storage for embedding hosts** — source: https://code.claude.com/docs/en/sessions
- **A resumed session restores conversation, model, agent, permission mode (terminal only, with exceptions), active goal and unexpired scheduled tasks; `--mcp-config`, `--settings`, `--plugin-dir`, `--fallback-model`, `--add-dir` must be passed again** — source: https://code.claude.com/docs/en/sessions
- **Session picker: `Space` previews, `Ctrl+R` renames, `Ctrl+A` all projects, `Ctrl+W` all worktrees, `Ctrl+B` current branch; pasting a PR/MR URL finds the session that created it; duplicate live names get a two-word suffix such as `auth-refactor-graceful-unicorn` (v2.1.232+)** — source: https://code.claude.com/docs/en/sessions
- **Unnamed sessions get a default display name (`<dir>-3f` style, v2.1.196+, not a resume handle) and a Haiku-generated title from the first prompt (usable with `--resume`); accepting a plan replaces the title with a plan-based one** — source: https://code.claude.com/docs/en/sessions
- **"Resume from summary": on Pro/Max, resuming a session idle for over an hour and over 100,000 tokens opens a dialog offering "Resume from summary" (runs `/compact` first), "Resume full session as-is", or "Don't ask me again"; the prompt cache has expired by then so the next request reprocesses full history either way** — source: https://code.claude.com/docs/en/sessions
- **Slash commands in `-p`: user-invoked skills expand from the prompt string; `/model`, `/effort`, `/fast`, `/color`, `/rename` accept a value as an argument (v2.1.205+); `/config key=value` changes a setting; `/mcp` with no argument prints a text status summary; terminal-only commands such as `/login` are unavailable** — source: https://code.claude.com/docs/en/headless
- **`/branch [name]` copies the conversation in-process; `claude --continue --fork-session` forks into a new process; `/export [filename]` writes a readable transcript; `/rewind` (aliases `/checkpoint`, `/undo`) offers "Restore code and conversation", "Restore conversation", "Restore code", "Summarize from here"; snapshots kept for the 100 most recent checkpoints; Bash-made file changes are not tracked** — source: https://code.claude.com/docs/en/sessions, https://code.claude.com/docs/en/checkpointing

### Permissions
- **`--permission-mode` accepts `default`, `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions`, or `manual` (alias of `default`); the built-in starting mode for `-p` is Manual on every plan; `dontAsk` denies anything not in `permissions.allow` or the read-only command set (useful for locked-down CI)** — source: https://code.claude.com/docs/en/cli-reference, https://code.claude.com/docs/en/headless
- **`--permission-prompt-tool` names an MCP tool to handle permission prompts in non-interactive mode; a `-p --resume` run resumes in plan mode only when `--permission-prompt-tool` is passed** — source: https://code.claude.com/docs/en/cli-reference, https://code.claude.com/docs/en/sessions
- **SDK evaluation order: hooks, deny rules, ask rules, permission mode, allow rules, then `canUseTool`; `canUseTool` returns `{ behavior: "allow", updatedInput }` or `{ behavior: "deny", message }`; `AskUserQuestion` also routes through it; the SDK warns with `CLAUDE_SDK_CAN_USE_TOOL_SHADOWED` when `bypassPermissions` makes the callback unreachable; a `PreToolUse` hook may return `defer` to let the process exit and resume later** — source: https://code.claude.com/docs/en/agent-sdk/permissions, https://code.claude.com/docs/en/agent-sdk/user-input

### Hooks
- **Event names include `SessionStart`, `Setup`, `UserPromptSubmit`, `PreToolUse`, `PermissionRequest`, `PermissionDenied`, `PostToolUse`, `PostToolUseFailure`, `PostToolBatch`, `Notification`, `SubagentStart`, `SubagentStop`, `TaskCreated`, `TaskCompleted`, `Stop`, `StopFailure`, `TeammateIdle`, `ConfigChange`, `CwdChanged`, `FileChanged`, `WorktreeCreate`, `WorktreeRemove`, `PreCompact`, `PostCompact`, `PreModelSwitch`, `PostModelSwitch`, `Elicitation`, `SessionEnd`** — source: https://code.claude.com/docs/en/hooks
- **Hook `type` values: `command`, `http`, `mcp_tool`, `prompt`, `agent`; common fields `if`, `timeout`, `statusMessage`, `once`, `async`; exit 2 blocks; JSON output supports `systemMessage`, `terminalSequence`, and `hookSpecificOutput.{permissionDecision, permissionDecisionReason, additionalContext, updatedInput, continue, stopReason, retry, updatedPrompt}`** — source: https://code.claude.com/docs/en/hooks
- **`Notification` matchers include `permission_prompt`, `idle_prompt`, `auth_success`, `elicitation_dialog`, `agent_completed`; hook input includes `session_id`, `transcript_path`, `cwd`, `permission_mode`, `effort`, `agent_id`; `terminalSequence` lets hooks emit desktop notifications, window titles and bells "without a controlling terminal" (changelog 2.1.141)** — source: https://code.claude.com/docs/en/hooks, https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md
- **`WorktreeCreate`/`WorktreeRemove` hooks replace the git worktree logic entirely (SVN/Perforce/Mercurial); the hook prints the created directory path on stdout; `.worktreeinclude` is not processed when a hook is used** — source: https://code.claude.com/docs/en/worktrees

### Worktrees, subagents, background agents
- **`claude --worktree <name>` / `-w` creates `.claude/worktrees/<name>/` on branch `worktree-<name>` (auto-name like `bright-running-fox` if omitted); `--worktree "#1234"` or a GitHub PR / GitLab MR URL creates `.claude/worktrees/pr-<number>`; reusing a name reopens the existing worktree; `worktree.baseRef` is `"fresh"` (default branch on remote) or `"head"`** — source: https://code.claude.com/docs/en/worktrees
- **`.worktreeinclude` (gitignore syntax) copies gitignored files such as `.env` into every worktree Claude creates; only files that match and are gitignored are copied** — source: https://code.claude.com/docs/en/worktrees
- **Isolation is enforced by four checks: file edits targeting the main checkout are blocked, commands whose cwd resolves to the main checkout are blocked, git redirects (`git -C`, `GIT_DIR`, `cd` into main) are blocked, and commands whose shape cannot be verified (brace expansion, unquoted heredocs) are refused with rewrite guidance; "You can't turn this check off"** — source: https://code.claude.com/docs/en/worktrees
- **Cleanup: on interactive exit a clean unnamed worktree is removed automatically; a dirty one prompts keep/remove; `-p` runs have no exit prompt and do not clean up; a periodic sweep removes subagent/background worktrees older than `cleanupPeriodDays` unless they hold changes or unpushed commits; Claude holds a `git worktree lock` while an agent runs** — source: https://code.claude.com/docs/en/worktrees
- **Resuming a session created in a worktree returns it to that worktree, including `-p --resume` and the Agent SDK (v2.1.212+); a deleted worktree resumes in the launch directory with the binding cleared** — source: https://code.claude.com/docs/en/worktrees
- **Subagent frontmatter (`.claude/agents/*.md`) supports `name`, `description`, `tools`, `disallowedTools`, `model`, `permissionMode`, `isolation: worktree`, `background`, `memory`, `hooks`, `skills`, `maxTurns`, `effort`, `mcpServers`; `isolation: worktree` gives a temporary worktree removed automatically when unchanged; per-session subagent cap default 200 (`CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION`, changelog 2.1.212)** — source: https://code.claude.com/docs/en/sub-agents, https://code.claude.com/docs/en/worktrees, https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md
- **`claude --bg "<prompt>"` dispatches a background session hosted by a supervisor (`claude daemon`); `claude agents` opens an agent view grouping sessions as Pinned / Ready for review / Needs input / Working / Completed; rows show state icon, name, a Haiku-generated one-line summary, age, and a PR label colored by check/review status; `Space` opens a peek panel where you can type a reply without attaching; `claude agents --json`, `claude attach <id>`, `claude logs <id>`, `claude stop <id>`** — source: https://code.claude.com/docs/en/agent-view
- **Background sessions move into an isolated worktree under `.claude/worktrees/` before editing (disable with `worktree.bgIsolation: "none"`); before finishing, Claude commits and pushes or opens a draft PR to preserve work; agent view fires terminal notifications and the `Notification` hook with `agent_needs_input` / `agent_completed`** — source: https://code.claude.com/docs/en/agent-view
- **Agent view keys: `Space` peek, `Enter`/`→` attach, `←` background/return, `Ctrl+S` group by state vs directory, `Ctrl+T` pin (keeps the process alive; idle processes otherwise stop after ~1 hour), `Ctrl+R` rename, `Ctrl+X` stop (twice within 2 s deletes), `Shift+↑/↓` reorder, `Ctrl+G` open the dispatch prompt in `$EDITOR`; attached sessions render fullscreen and double `Ctrl+C` detaches; `claude agents --permission-mode plan --model opus --effort high` sets defaults for sessions dispatched from that view; `claude daemon status` / `claude daemon stop --any --keep-workers`** — source: https://code.claude.com/docs/en/agent-view
- **For a `"fresh"` worktree base, Claude Code fetches the default branch when the repo has not been fetched in 24 hours (capped at 5 s, falling back to the cached ref); a reopened worktree resets to the default branch only when it is clean, still on its generated branch, and has no commits of its own or its PR was merged and the remote branch deleted (v2.1.208+)** — source: https://code.claude.com/docs/en/worktrees
- **Worktrees share the repository `.git` directory, project-scope plugins (v2.1.200+) and saved permission approvals with the main checkout: "Yes, and don't ask again" in a worktree writes the rule to the main checkout's `.claude/settings.local.json` (v2.1.211+)** — source: https://code.claude.com/docs/en/worktrees
- **Agent teams (experimental, `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`): lead plus teammates each with their own context, a shared task list with file-locked claiming and dependencies, mailboxes at `~/.claude/teams/{team}/inboxes/{agent}.json`; not spawned under `-p`; agent teams "use approximately 7x more tokens than standard sessions when teammates run in plan mode"** — source: https://code.claude.com/docs/en/agent-teams, https://code.claude.com/docs/en/costs

### Cost, usage, telemetry
- **`/usage` (aliases `/cost`, `/tokens`) prints `Total cost`, API and wall durations, code changes, and `Usage by model` with input/output/cache-read/cache-write tokens and per-model dollars; totals reset on `/clear` (v2.1.211+); a `Prompt cache (main)` line shows hit ratio, misses, expected rebuilds and warm/cold (v2.1.251+)** — source: https://code.claude.com/docs/en/costs
- **Cost is computed locally at list price unless a managed `modelPricing` setting supplies contracted rates (`multiplier` and/or per-model `overrides`, v2.1.242+); `--max-budget-usd` compares against the same figure; the 1.1x data-residency premium is included since v2.1.239** — source: https://code.claude.com/docs/en/costs
- **Plan usage breakdown attributes recent usage to skills, subagents, plugins and MCP servers, flags behaviors that account for 10%+ of usage (long context, cache misses), and lists the heaviest `/loop` tasks; `d`/`w` toggles 24 h vs 7 days** — source: https://code.claude.com/docs/en/costs
- **OpenTelemetry (`CLAUDE_CODE_ENABLE_TELEMETRY=1`, `OTEL_METRICS_EXPORTER=otlp|prometheus|console`): metrics `claude_code.cost.usage`, `claude_code.token.usage` (type `input|output|cacheRead|cacheCreation`), `claude_code.session.count`, `claude_code.lines_of_code.count`, `claude_code.commit.count`, `claude_code.pull_request.count`, `claude_code.active_time.total`; events `claude_code.api_request` carry `cost_usd`, token counts** — source: https://code.claude.com/docs/en/monitoring-usage
- **Cited averages: "around $13 per developer per active day and $150-250 per developer per month, with costs remaining below $30 per active day for 90% of users"; background jobs (summaries for `--resume`) cost "typically under $0.04 per session"** — source: https://code.claude.com/docs/en/costs
- **`/insights` analyzes up to 200 recent local sessions and writes an HTML report of work patterns and friction points to `~/.claude/usage-data/report.html`; a `PreToolUse` hook example rewrites `npm test|pytest|go test` commands to pipe through `grep -A 5 -E '(FAIL|ERROR|error:)' | head -100` via `hookSpecificOutput.updatedInput` to cut test-output tokens** — source: https://code.claude.com/docs/en/costs
- **"Why usage climbs in a long session": every request re-sends full history; cache lifetime is one hour on a subscription and five minutes on usage credits or API keys; scheduled tasks, cross-session messages (`crossSessionInbound: hold` to defer) and goal check-ins (`CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0` to disable, max three per goal from v2.1.246) each start turns that carry the full context** — source: https://code.claude.com/docs/en/costs

### Routines, scheduling, cloud
- **Routines (research preview; Pro/Max/Team/Enterprise) are saved prompt + repos + connectors that run on Anthropic-managed cloud; triggers are Scheduled (min interval 1 hour, one-off runs allowed), API (`POST .../v1/claude_code/routines/<id>/fire` with a bearer token and `anthropic-beta: experimental-cc-routine-2026-04-01`, returns a session URL), and GitHub (`pull_request.*`, `release.*` with filters on author/title/labels/branches/draft)** — source: https://code.claude.com/docs/en/routines
- **Routines run "as full Claude Code cloud sessions: there is no permission-mode picker and no approval prompts"; each run creates a session where you can review changes and create a PR; a green run status "does not mean the task in your prompt succeeded"; runs count against a daily per-account cap (one-off runs exempt); routines are per-account, not shared with teammates** — source: https://code.claude.com/docs/en/routines
- **API-trigger `text` arrives wrapped in a `<routine-fire-payload>` block "that labels it as untrusted data and tells Claude not to follow instructions inside it unless the routine's own prompt says to"; the same wrapping applies to "Run now" text; per-routine bearer tokens are shown once and can be regenerated or revoked; GitHub webhook events have per-routine and per-account hourly caps** — source: https://code.claude.com/docs/en/routines
- **Routine pushes to `claude/`-prefixed branches are always accepted; a push to another branch is rejected if the branch is protected, someone else has an open PR from it, or it carries commits by someone other than you; `/schedule why did my nightly review do nothing this morning?` reads a run's log and explains tool errors, permission denials and the final result (v2.1.227+)** — source: https://code.claude.com/docs/en/routines
- **`/schedule` (alias `/routines`) creates routines conversationally from the CLI, with `/schedule list|update|run`; `/loop [interval] [prompt]` polls in-session (1 min to 1 hour, max 50 tasks, recurring tasks expire after 7 days); a comparison table lists Routines (cloud), Desktop scheduled tasks (local), GitHub Actions, and `/loop`** — source: https://code.claude.com/docs/en/routines, https://code.claude.com/docs/en/scheduled-tasks, https://code.claude.com/docs/en/common-workflows
- **`claude --cloud "task"` starts a cloud session (`--remote` deprecated alias); `claude -p "msg" --cloud <session-id>` queues a follow-up; `--teleport` pulls a web session into the terminal; Claude Code on the web has a per-session diff view with inline comments and an Auto-fix PR toggle that reacts to CI failures and review comments; "no separate compute charge for the cloud VM"** — source: https://code.claude.com/docs/en/cli-reference, https://code.claude.com/docs/en/claude-code-on-the-web

### Agent SDK, plugins, MCP
- **`@anthropic-ai/claude-agent-sdk` / `claude-agent-sdk` `query()` options include `permissionMode`, `canUseTool`, `hooks`, `resume`, `forkSession`, `sessionId`, `persistSession`, `settingSources` (`user|project|local`, pass `[]` to disable), `agents`, `mcpServers`, `maxTurns`, `maxBudgetUsd`, `effort`, `outputFormat: { type: 'json_schema', schema }`; the result message has `total_cost_usd`, `usage`, `num_turns`, `structured_output`, `permission_denials[]`** — source: https://code.claude.com/docs/en/agent-sdk/typescript, https://code.claude.com/docs/en/agent-sdk/python
- **Plugins: `.claude-plugin/plugin.json` plus `skills/`, `commands/`, `agents/`, `hooks/hooks.json`, `.mcp.json`; marketplaces via `.claude-plugin/marketplace.json`, `/plugin marketplace add owner/repo`, `/plugin install name@marketplace`; team pinning with `extraKnownMarketplaces` and `enabledPlugins`; "Custom commands have been merged into skills"** — source: https://code.claude.com/docs/en/plugins, https://code.claude.com/docs/en/plugin-marketplaces, https://code.claude.com/docs/en/skills
- **`claude mcp add [--transport http|sse|stdio] [--scope local|project|user] <name> ...`; `.mcp.json` supports `${VAR}` / `${VAR:-default}`; `MCP_TIMEOUT` (30 s default startup wait under `-p`), `MAX_MCP_OUTPUT_TOKENS` (25,000 default); MCP tool definitions are deferred by default via tool search** — source: https://code.claude.com/docs/en/mcp, https://code.claude.com/docs/en/headless

## 2. OpenAI Codex CLI

- **`codex exec` "Run Codex non-interactively. Stream results to stdout or JSONL and optionally resume previous sessions"; flags: `--json` (newline-delimited JSON events), `-o/--output-last-message <file>`, `--output-schema <json-schema-file>`, `--ephemeral` ("Run without persisting session rollout files to disk"), `--skip-git-repo-check`, `-s/--sandbox read-only|workspace-write|danger-full-access`, `--color`, `-c key=value` overrides, `-C/--cd`, `-i/--image`, `-m/--model`, `-p/--profile`, prompt from stdin with `-`; `--full-auto` is deprecated in favor of `--sandbox workspace-write`** — source: https://developers.openai.com/codex/cli/reference (served from https://learn.chatgpt.com/docs/developer-commands?surface=cli)
- **Default: `codex exec` "runs in a read-only sandbox by default", streams progress to stderr, prints the final message to stdout; CI auth via `CODEX_API_KEY=<key> codex exec --json "task"`** — source: https://learn.chatgpt.com/docs/non-interactive-mode
- **JSONL event types: `thread.started`, `turn.started`, `turn.completed`, `turn.failed`, `item.started`, `item.updated`, `item.completed`, `error`; item types `agent_message`, `reasoning`, `command_execution` (command, aggregated_output, exit_code, status), `file_change`, `mcp_tool_call`, `collab_tool_call`, `web_search`, `todo_list`, `error`; `turn.completed.usage` has `input_tokens`, `cached_input_tokens`, `cache_write_input_tokens`, `output_tokens`, `reasoning_output_tokens`** — source: https://raw.githubusercontent.com/openai/codex/main/codex-rs/exec/src/exec_events.rs, https://learn.chatgpt.com/docs/non-interactive-mode
- **Resume: `codex exec resume --last "<task>"` or `codex exec resume <SESSION_ID>` (UUID or session name); `--all` includes sessions outside the cwd; interactive `codex resume --include-non-interactive`; also `codex fork`, `codex archive`, `codex delete`; sessions live under `~/.codex/sessions` (`CODEX_HOME`)** — source: https://learn.chatgpt.com/docs/developer-commands?surface=cli, https://learn.chatgpt.com/docs/codex/cli
- **Sandbox: macOS Seatbelt; Windows native sandbox in PowerShell or the Linux sandbox under WSL2; Linux uses `bubblewrap` with a bundled fallback; config `sandbox_workspace_write.writable_roots`, `.network_access` (bool); `.git`, `.agents`, `.codex` stay read-only even in writable modes; `codex sandbox` runs arbitrary commands inside the sandbox** — source: https://learn.chatgpt.com/docs/sandboxing, https://learn.chatgpt.com/docs/config-file/config-reference, https://learn.chatgpt.com/docs/agent-approvals-security
- **Approval policy `-a untrusted|on-request|never` (config also allows `{ granular = {...} }`); default preset "Auto" = `--sandbox workspace-write --ask-for-approval on-request`; `--yolo` disables both; `approvals_reviewer = "auto_review"` routes eligible approvals to an automatic reviewer** — source: https://learn.chatgpt.com/docs/developer-commands?surface=cli, https://learn.chatgpt.com/docs/agent-approvals-security
- **In MCP-server mode approvals surface as JSON-RPC requests `applyPatchApproval { conversationId, callId, fileChanges, reason?, grantRoot? }` and `execCommandApproval { conversationId, callId, command, cwd, reason? }`; the client replies `{ decision: "allow" | "deny" }`; `codex mcp-server` emits `codex/event` notifications** — source: https://github.com/openai/codex/blob/main/codex-rs/docs/codex_mcp_interface.md

### GitHub Actions
- **`strategy.matrix` with `include`/`exclude`; `max-parallel`; `fail-fast` defaults to `true` and cancels all in-progress and queued matrix jobs on the first failure; `continue-on-error: true` keeps other matrix jobs running; a matrix "can generate a maximum of 256 jobs per workflow run"** — source: https://docs.github.com/en/actions/writing-workflows/choosing-what-your-workflow-does/running-variations-of-jobs-in-a-workflow, https://raw.githubusercontent.com/github/docs/main/data/reusables/actions/jobs/section-using-a-build-matrix-for-your-jobs-failfast.md, https://docs.github.com/en/actions/reference/limits
- **`needs`: "If a job fails or is skipped, all jobs that need it are skipped unless the jobs use a conditional expression"; `always()` "returns `true`, even when canceled" (docs recommend `if: ${{ !cancelled() }}` for hang-prone jobs); `failure()` true if any ancestor failed; job `outputs` flow to dependents via `needs`, and "Outputs containing secrets are redacted"** — source: https://raw.githubusercontent.com/github/docs/main/data/reusables/actions/jobs/section-using-jobs-in-a-workflow-needs.md, https://docs.github.com/en/actions/writing-workflows/choosing-what-your-workflow-does/evaluate-expressions-in-workflows-and-actions, https://raw.githubusercontent.com/github/docs/main/data/reusables/actions/jobs/section-defining-outputs-for-jobs.md
